# Goal G — frozen common-category evaluation protocol (v1)

**Capability.** Given a question about two named entities and two visible official supporting-evidence documents, answer the *shared category or attribute value* requested by the original question. This is an evaluation set for evidence-to-answer behavior under a synthetic two-search history, not an end-to-end retrieval test.

**Source and budget.** Use only the two previously acquired official HotpotQA `distractor/train` Parquet shards, verified against `download-provenance.json`. Inspect only `id`, `question`, and `type` across the shards to locate possible questions. Sort matching source IDs by `SHA256("v133-goal-g-v1" + source_id)`. Open `answer`, `supporting_facts`, and `context` for at most 100 eligible source rows, stopping after 20 fully qualified cases. No other source expansion.

**Question criteria.** Keep the original question and official answer unchanged. Admit an open-ended question about a common category or common property of two entities. Exclude yes/no, single-entity, date/order, and answer-granularity-ambiguous questions. Two distinct supporting titles must each provide direct evidence of the *same* answer category/property; mere word occurrence is insufficient. Missing or contradictory evidence fails. The two source documents are ordered by their first occurrence in the official supporting-fact list. Extra supporting titles fail rather than being silently omitted.

**Frozen metadata locator.** Case-insensitive regex on the question: `\b(both|share|shared|common|same|each)\b`. This only recalls candidates; manual evidence review decides eligibility. Exclude exact `yes`/`no` answers after opening a row. No model scores or historical target answers affect locator order.

**Exposure and isolation.** Exclude project-exposed source IDs and normalized question duplicates from v117/v118 training, v122 sources, v123 and v130 screening, and Goal C/D train/dev indexes. Screening history counts as project exposure for this fresh evaluation set. Check source ID, official evidence titles/IDs, named question entities and clear aliases against the actual training/dev inventory and other chosen cases. Generic answer-category words are not entity keys. Unknown exposure or unresolved entity overlap fails. This verifies project-level isolation only; foundation-model pretraining history is unknown.

**Input rendering.** System: `You are an evidence-driven retrieval agent. Output one JSON search or answer action, using visible evidence only.` User: original question. Search 1 is the exact original question; tool 1 returns the first official evidence document. Search 2 is the exact first document text; tool 2 returns the second document. Neither search sees the answer or future evidence. Target: `{"action": "answer", "answer": <original official answer>}` with JSON serialization preserving Unicode. Thinking is disabled. This deliberately matches Goal E's aligned dev structure and is synthetic.

**Review.** Send identical anonymous packets containing the original question, both visible documents, proposed answer and this protocol to DeepSeek and an isolated GPT-6 Luna reviewer without historic context or other votes. Each independently checks capability fit, two-sided direct support, answer granularity, ambiguity, and leakage. The old reviews do not transfer to new cases. Two mechanically valid approvals are required. A semantic rejection or disagreement excludes the case. At most one technical correction per invalid vote; never resend an unknown-outcome request.

**CPU acceptance.** With the installed AutoDL tokenizer/processor, use the real `encode_assistant_only` function. Check exact generation/supervision prefix equality, selected final assistant, causal label positions, right-padding mask, terminator, complete question/evidence rendering, no target-message leakage, and prompt/target/total limits 2048/128/2176. Distinguish answer-value tokens from JSON/ending tokens by offsets; mark boundary-crossing tokens ambiguous and exclude them until resolved. No weights, generation, SFT or GPU.

**Freeze and report.** Save input whitelist and SHA-256s, sorted locator metadata, every opened-row disposition, exposure/isolation decisions, reviewer packets/votes, CPU results, and an immutable evaluation JSONL. Report `cpu_ready`, `evaluation_isolation_verified`, `dual_review_complete`, `qualified_count`, and `unmet_conditions`. If fewer than 20 pass within the budget, retain the qualified subset and stop.
