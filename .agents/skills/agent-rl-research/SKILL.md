# 项目方向

目标：面向预算约束多跳问答的可审计 Agent RL 系统。贡献同时包含可复现 harness 和经过可信对照的小模型策略。Qwen3.5-0.8B + LoRA 足以承载项目，模型规模不是完成标准。

研究问题：有限上下文和检索预算下，RL 能否改善何时搜索、如何利用证据、何时停止？

## 执行原则

- 开始工作先读项目 README、最近任务总结、对应实验报告和实现；本文提供方向，不把历史指标当当前事实。
- 固定任务顺序、独立 corpus、检索器版本、reward、起点 adapter、量化、上下文、seed 与代码指纹；task_limit 不得隐式改变 corpus。
- 核验 loss、mask、LoRA-only、固定 reference、old/current 输入重放与负轨迹完整性。无完整测试和审计证据，不宣称框架稳定有效。
- system/user/tool observation 不参与 policy loss；gold/support titles 只用于评估，不能指导检索或上下文裁剪。
- 先小规模门槛验证，再扩大任务和 seed；OOM、非有限值、基础设施错误或约定 gate 失败后保留证据并停止后续训练。
- 临时目录权限问题与断言失败分别记录，但权限错误不能算测试通过。
- 数据集封存规则沿用实验协议，不读取 data/hotpot-agent-v072/final-test.jsonl 调参。
- 重复率为零时报告地板效应。使用预定义困难场景和空检索诊断，不按模型失败挑选评测题；人工提供的历史动作不算模型重复行为。
- 停止诊断必须分开报告空检索后回答、部分覆盖后继续搜索、完整覆盖后回答及其正确率；support 覆盖只用于离线标签，不能等同于可推导的正确答案。预算压缩超过预注册阈值时，该探针只能说明上下文压力，不得启动基于它的训练或解释为停止能力。
- 固定前缀复现须真实比较 action、prompt、observation、reward，corpus hash 相同不等于轨迹已复现。
- 多 seed 对比使用同一起点与协议，报告所有 seed 和失败结果，不挑最优 seed。
- 更高显存用于独立研究长度/规模影响，不能替代训练正确性。云端先复现本地配置，再改变单一变量。
- 单次下载或同一安装任务预计累计下载超过 1GB（1,000,000,000 字节）时，必须在执行前说明内容、用途、预计大小与保存位置并取得用户确认。大小未知先查询；不得拆分下载绕过该约束。
- v0.8.7 起，采样与 old/current/reference logprob 必须重放保存的 prompt token IDs/attention mask；重渲染消息不算输入重放。`compact-v2` 的引用键包括 ID、标题和正文哈希，预算失败与缺失显存字段均为失败或不可验证，不能按零处理。

## 简历交付标准

一条命令离线演示；有测试与梯度/奖励审计；同协议 SFT/GRPO、多 seed 对照；至少一项有消融支持的设计；代码、数据、模型哈希及运行报告可追溯。历史开发集提升不能作为修正后实现的效果证明。

简历结论仅引用已完成且可核对的实验；负结果及系统故障定位也属于贡献。每次大任务补中文文档，区分实现、实测、推断与未验证内容。权重、数据库和原始运行产物不提交。
