## 新入口和强制顺序

`scripts/evaluate_v122_unified.py` 的四组输出都保持 `search/answer` 两种现有动作。Q 增加查询提示和表面实体依据拦截，S 增加证据完整性提示；关系是否真正受到引用支持仍由离线双审判断。查询重复不执行、不占搜索额度，仅准一次同协议修复。搜索额度耗尽后仍请求搜索则弃答并计错。

1. `preflight`：冻结代码、数据、模型、提示和解码设置哈希。四组各50次原始模型调用，搜索与回答预设状态各25个；每组至少49次通过解析、没有截断且与设置哈希一致，否则不得进入开发集。
2. `fixed`：四组共用同一首轮查询和 BM25-v2 top3，逐题复核首轮 top3 ID；运行完整50题固定状态续跑。只有候选至少31/50、比同期A净增至少3题、F1不降、保留v118的14/14及v120的至少25/26、协议率≥98%，才可提交盲审并考虑完整端到端运行。
3. `audit_v122_api.py` 生成不含 gold、评分、问题ID或组别的匿名材料，经授权的 DeepSeek 与最多一名独立任务 agent 分别审核。`merge_v122_audit.py` 逐条核验当时可见证据的引用、覆盖和答案支持分歧；仅完整且无选中方案支持争议的审核可放行端到端运行。
4. `full-e2e`：先核对固定状态双审批准，再完整跑50题。端到端成绩与v120端到端基线比较：至少29/50、F1不降、保留v118的14/14、保留v120的至少25/26、协议率≥98%。最终仍须完成答案支持双审，不能只看数值门槛。

若协议预检失败，只修协议并重新冻结设置，不启动 SFT。协议稳定但语义错误持续存在时，才构造新的训练来源配对样本和从未开发使用过的内部50题；两者双审和隔离通过后，从v101重新开始5步 smoke及单次50步正式训练。数据不足、审核分歧、远端GPU或权重核验失败均阻止训练。
