# v118 错误复核与正确率优先改进

本次只分析已完成的内部试验，未运行模型、调用外部教师、开启AutoDL或读取独立100题/final-test。原预注册指标及冻结产物保持不变。本报告是主agent事后诊断，不充当新增独立双审，也不生成训练标签。

## 1. 结论与可量化证据

主要瓶颈是多跳关系未完成时提前回答，以及证据完整时抽取了错误实体/属性。纯粹扩大数据量、强制增加搜索次数或继续训练v118，都没有被当前结果证明有效。

- 内部端到端EM：v101 9/50，v112 24/50，v118 14/50。v112是当前这套内部环境下最强的本地参考，尚未经独立100题验证。
- v112对而v118错11题，反方向1题，净差10题。11题中9题是v118只搜索一次、v112搜索两次；1题两者都搜索两次但v118跟错实体；1题是相同可见输入下的回答抽取退化。
- 上述9题中5题的第二步prompt token IDs完全相同：歌手生日、Don Calfa电影导演、Schubert国籍、图书馆所属大学成立年、Pools of Darkness作者任职时长。v112继续搜索正确桥接实体，v118立即回答。该比较定位了相同状态上的动作差异，但不是把某个动作替换进去后的完整因果试验。
- v118有35题只搜索一次，其中严格EM正确4题、未匹配31题。这是现象，不证明再搜一次必然有效。
- v118充分证据50状态：37个严格EM正确、11个回答未匹配、2个继续搜索。13个未匹配状态都没有发生prompt截断或正文裁剪，因此这些固定状态的错误不应首先归因于2048 token预算。
- v101→v118的充分证据固定状态变化为1增3退：比较乐队人数改善；San Jose和Getty Images两题由正确回答变为继续搜索；PARIS网站出版公司由正确公司名变为网站名。不能仅凭这3例泛化为整体遗忘。

## 4. 审核统计的重要更正

旧semantic-gate的492项不是492道错题，也不能直接解释为492个独立语义问题。它叠加了196个候选分歧、26个候选不确定和270个引用异常标记。

逐项检查发现，270个异常中的265个是对JSON字符串转义形式做匹配产生的标记。对应301条引用（Luna56、DeepSeek245），均可在同候选、同动作时刻的工具消息解析出的文本中精确找到。不能据此指责审核者引用了不存在的证据，先前“60个状态、13个变化题引用仍无效”的说法必须撤回为待重算。

剩余5个是搜索结果引用标记：2个涉及不换行空格与普通空格差异；3个引用了当次搜索结果中不存在的AKA/San Jose句子，必须继续隔离。前者也不能默默放宽逐字标准，应保留原字符或做有来源映射的规范化。

在逐篇解析工具文档并重新校验后，修正报告实际留下272项未解决标记：196项候选分歧、26项不确定、45项动作前引用无效、5项搜索结果引用问题。45项中，42项引用跨越了序列化文档边界或使用了JSON结构文字，另3项仍包含转义字符而不等于文档原文。原先265项的误报修复与新识别的45项问题可以同时成立，不能简单从492减去265后当作最终结果。搜索动作的“证据支持”也存在判定口径混用：问题未获解答不等于搜索不合理。应分开回答支持、搜索必要性、查询依据和相关新增事实。

旧报告标出的唯一端到端候选退化对应PARIS题。本次核对实际可见文档和相同prompt确认：它确实是出版公司/网站实体混淆。数值门槛依然失败，无需开启独立100题。保留原始文件以便追溯，不用本次事后复核改写既定成绩。

## 5. 训练数据与真实轨迹的差距

对冻结345条训练导出的静态统计：156回答、189搜索；其中101条搜索目标直接是可见文档中的连续子串，搜索目标词数中位数11、最大57，有30条超过20词。385个历史搜索动作中193个只有一个词。训练状态中的177条搜索只有一次工具观察；答案样本104条有一次工具观察、52条有两次；空证据搜索12条。

这些不证明长查询或短历史查询本身错误，但说明“已达到样本数量和动作比例”不能保证覆盖模型实际的失败状态。当前最缺的可能是自然问题第一轮检索后、含诱人错误日期/人名/公司且仍缺一跳的真实状态，以及证据齐全时必须停止的对应状态。不得直接把这批内部题或其答案加入SFT。

## 6. 正确率优先的执行顺序

1. **先修计量与审核口径。** 保留原EM，同时增加预先冻结、三模型统一的语义等价诊断；引用改为候选ID、动作时刻、文档ID、可见span和原文hash绑定，对真正可见的解析文本校验。修复搜索和回答共用一个模糊verdict的做法。对Bio等“现有文字已直接给出作者却要求继续搜索”的状态重新检查充分性；只复核已定位问题，不推倒重做全部数据。
2. **优先验证完整关系链与回答条件。** 在开发环境要求回答前定位目标实体、目标关系、答案类型和支持句；证据已齐则提取正确字段，未齐则搜索缺失实体/属性。所有字段只从问题和当前可见证据产生。先做同状态重放，再做完整端到端对照；不强制两次搜索，也不先扩大top-k或上下文。运行时若用外部模型复核，必须另记混合流程成绩，不能计作本地模型提升。
3. **针对检索偏移修查询。** 优先处理人物生日交叉筛选、Wire/天线、所属机构和人物关系。先测实体锚定短查询与缺失属性查询；检索有效性要求补入缺失关系。BM25重排是否有收益要单独验证，避免同时改训练、检索和模板而无法归因。
4. **再补训练来源的真实失败状态。** 固定v101/v112在未用于内部验收的训练问题上采集轨迹，加入“同类型干扰答案存在但缺关键关系”的搜索状态，和“补齐后必须回答”的配对状态；加入已正确回答的回放样本防退化。保留合格通用样本。按已暴露机制补覆盖，不以再增加几千条程序构造记录代替质量。所有新目标继续双审；错误动作只用于诊断或独立对比任务，不直接作SFT标签。
5. **最后才注册下一次训练。** 当前v112保留为强参考，v101保留为原基线，v118作为本轮失败候选留档。先判断收益来自查询/停止时机还是回答抽取，再决定下一轮训练起点，避免因v118版本更新就继续沿用。当前50题经本次分析已是开发诊断集；下一次确认性验收需事先冻结未暴露内部集，独立100题继续封存。优先目标是端到端正确数增加、原正确答案保留、证据完整时不答错，而非只提升搜索率。

原始依据位于本地 `backups/v118/extracted/runs/v118/eval/`、`backups/v118/reviews/` 及 `data/evidence-sft-v117/frozen/train.jsonl`。本报告不宣称改进方案已经带来新成绩。
