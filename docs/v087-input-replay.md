# v0.8.7：输入重放与完整上下文推理对照

本版本修正 v0.8.6 的证据审计缺口，不改变模型、SFT 起点、BM25-v2、原始语料、reward 或冻结题目顺序。封存最终集不会被读取。

## 修复内容

- `legacy` 在输入本来能容纳时恢复原始 tool JSON；不再被 compact 编码悄悄改写。
- 新增 `compact-v2`：重复引用以文档 ID、标题和正文 SHA256 共同判定；缺失 ID 不合并；相同 ID 内容冲突保留完整文本。
- 文本只在句子边界缩短，保存原文偏移、内容哈希与引用目标；v2 不删除动作历史或检索文档，无法容纳时记录 `context_budget_error`。
- 采样后的 old logprob 直接重放采样时保存的 prompt token IDs 与 attention mask，不重新渲染消息。
- case 级预算失败、模型异常与显存缺失均保留在结果中，不能从分母消失。

## 已执行的 tokenizer 审计

冻结输入为 v0.8.5 的 120 个 case。`compact-v2` 的结果如下；这些是编码与预算事实，不是模型质量结论。

| 预算 | 有损正文裁剪 case | 预算失败 | 文档删除 | 历史删除 | 可见 support 保留 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 768 | 25.83% | 30 | 0 | 0 | 100% |
| 1024 | 22.50% | 5 | 0 | 0 | 100% |
| 2048 | 0% | 0 | 0 | 0 | 100% |

因此 768 不具备训练启动条件；即使更长纯推理通过，也不会自动提高本机反向传播预算或启动 GRPO。后续 GPU 探针必须逐 case 保存错误与显存，并以 `peak_reserved_gb` 缺失为不可验证，而非 0。

## 已完成的 2048-token 纯推理

2048 token 的 120/120 case 已在本机完成；无预算失败，峰值 allocated/reserved 分别为 1.709/3.223 GiB（设备进程级显存不可用，明确记为 unknown）。整体回答率为 100%，新增搜索率为 0%。四种条件的 strict EM 分别为 one-hop 33.3%、two-hop 43.3%、空检索 6.7%、重复历史 30.0%；对应 token F1 为 0.383、0.611、0.119、0.372。

这些结果只说明在预置历史的一步探针中，长上下文能完整容纳现有证据；它不是自主多步 Agent 质量，也不能证明停止策略正确。由于修正后的 768 审计未通过，768/1024 的完整 GPU 对照与后续训练被门槛阻止，不以不完整 case 计算指标。

## 运行命令

```powershell
mini-agent-rl stop-probe --frozen-cases reports/v085-stop-768/cases.jsonl `
  --observation-encoding compact-v2 --max-input-tokens 2048 --output reports/v087-stop-2048
```

模型权重、SQLite、报告与轨迹均为本地忽略产物。本版本是候选版本，所有门槛完成前不创建 tag。

## 收口实验：compact-v3

compact-v3 保留 compact-v2 产物语义，单独实现低排名优先裁剪。完整回归在唯一可写临时目录运行，结果为 `57 passed`。冻结 120-case 的完整运行结果如下：

| 预算 | 预算失败 | 有损 case | 正文字符保留 | reserved 峰值 | 门槛 |
| --- | ---: | ---: | ---: | ---: | --- |
| 768 | 34/120 | 22.5% | 66.7% | 2.473 GiB | FAIL |
| 1024 | 8/120 | 20.0% | 87.8% | 3.248 GiB | FAIL |
| 2048 | 0/120 | 0% | 100% | 3.223 GiB | PASS（纯推理） |

完整输入长度为 min 139、P50 721、P95 1436、max 1883 token。768→1024 的总体 strict EM/F1 增加 10.0/10.69 个百分点，但主要来自预算失败减少；1024→2048 的 strict EM 不变，F1 增加 2.36 个百分点。对照以 30 道题为配对单位，四个条件没有被当作 120 道独立题目。

三个预算均完成全部 120 个 case；预算失败也在分母中。768 与 1024 未达到训练条件，因此本机未执行梯度探测或 GRPO。下一条冻结路线为单卡 24GB、2048-token、5×4 冒烟，配置见 `configs/v087-single-gpu-24gb-2048.toml`。Linux 设备尚未实际运行，模型内容哈希必须与本机一致。

`configs/v087-probe-{768,1024,2048}.toml` 提供可重复执行的子进程监督入口，每档 30 分钟硬超时、独立 run/output 目录且拒绝覆盖。本次三档实测在这些配置落盘前已经完成，因此报告同时保留这一运行方式限制。

历史更正：先前 `reports/v087-stop-768` 是人工中断的部分结果，1024 当时未运行；它们不属于本次完整对照。support 保留率仅以成功编码且原始覆盖非零的样本为有效分母，不能替代正文保留率或语义证据充分性。
