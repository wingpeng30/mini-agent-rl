# v119 正确率机制诊断与下一次 GPU 重放

## 本地已完成的三项实验

1. **双审引用和维度复算。** 在不改写原v118报告的前提下，引用改为从各候选的动作前工具消息解析逐篇文档正文，不接受跨文档的序列化片段。修正后的语义门槛仍失败：272项未解决标记，包括196项分歧、26项不确定、45项动作前引文问题和5项搜索结果引文问题。两名审核者的输入和判断没有重写。新报告在本地 `backups/v118/reviews/semantic-gate-corrected.json`。原数值门槛再次代入此修正报告，仍为`internal_eligible=false`。
2. **分开评估搜索的三件事。** 对v118在50个“不足证据”状态中的42次实际搜索，独立双审仅有20次一致认为top3补到了相关的新事实；14次一致认为没有，6次有分歧，2次引用未通过。搜索必要性、查询依据、新事实三项同时一致为“是”的只有17次。可见原来的42/50是动作率，不等于有效补搜索率。这个复算只描述审核者意见，不能替换原预注册结果或为争议状态生成标签。
3. **观察已有第二跳与证据候选上限。** v112答对而v118答错11题：9题是v118只搜索一次、v112两次，1题两者都搜索两次但v118偏离目标，1题在相同输入中回答错实体。在9道提前回答题中，5道第二步输入token完全相同；v112的下一次搜索结果在这5道都包含其最终正确答案字符串。v112的10次可用第二跳结果均含最终答案字符串。这是历史轨迹的机会诊断，不是v118执行该搜索后的成绩。

对v118的36道端到端错题，34题给出了答案。仅12题的官方答案字符串逐字出现在最终回答前的文档中；表达等价可能使这一数字低估真正的证据覆盖。一个不依赖模型、只抽文档标题、专名和日期的候选提取器，覆盖34题中的9题，候选数中位数37、最多90。这个宽松原型达不到覆盖大多数错题的条件，现阶段没有依据优先训练独立候选选择器。

原始数据与复算报告分别位于 `backups/v118/extracted/runs/v118/eval/`、`backups/v118/reviews/v119-review-dimensions.json`、`backups/v118/reviews/v119-retrieval-opportunity.json` 和 `backups/v118/reviews/v119-evidence-span-screen.json`。所有步骤只读取冻结的50题内部结果和训练侧代码，不接触封存的独立100题与final-test。

## GPU 小实验：补第二跳后能否回答

已实现`scripts/replay_v119_bridge.py`，锁定上述5道第二步完全相同的案例。重放只对v118 adapter执行一次新动作：将v112在相同输入下生成的第二跳搜索及其真实top3结果放入历史，再由v118回答或继续搜索。结果与v112第三步的prompt token和哈希逐条核对；gold只在生成之后评分，不进入模型输入。此设计检验“补齐证据后v118是否能回答”，不能冒充新内部验证或完整的反事实端到端效果。若5题仍多错，答案生成/关系抽取优先；若明显改正，搜索时机和查询优先。

重放已在原v118实例的RTX 4090上完成。实例语料、评分文件和v118 adapter哈希与冻结记录一致；重放入口同时核验基础模型文件哈希，并逐例核对实际输入token与v112对应输入。五个回顾性挑选的案例均在补入v112真实第二跳搜索及top3结果后选择回答，五题normalized EM和token F1均为1.0。完整逐案原始结果保存在AutoDL `/root/autodl-tmp/v119-bridge/replay.json`（3.7 KB）。

这五题是从已暴露的内部结果中按共同输入条件回顾性挑选，且使用v112实际找到的结果作为补入证据；因此5/5只表明v118在这五个相同输入上能利用补齐的证据作答，不能估计未见题的正确率，也不能证明自动检索策略带来因果收益。它支持继续优先检验搜索停止时机与第二跳查询；要判断真实收益，下一项实验应在固定题集上让v118自己生成第二跳查询并检索，再与当前流程配对比较。

## 固定开发题上的自生成第二跳查询

随后在同一组5个回顾性开发状态上重放v118的原生决策，并另设“本次诊断必须搜索一次”的明确指令，以便在模型原生选择提前回答时仍测到查询本身。原生决策5/5均回答、0/5搜索，且回答EM为0/5；因此在这些状态里，实际阻断第二跳的是停止/动作选择。受控诊断5/5均生成搜索动作及非空查询，固定BM25 top3中3/5逐字出现目标答案，补搜后回答3/5正确（EM），正确的三题F1均为1.0，另两题EM/F1均为0。目标答案字符串只作可复现的检索命中下界：它会漏掉语义等价证据，也不能单独证明文档足以支持完整答案。

查询与top3的例子显示了两种结果：关于Kylie Minogue出生日期、Franz Schubert国籍和Portland State University建校年份的查询，其top3含目标答案字符串且模型答对；关于《Rude Awakening》及《Pools of Darkness》合著者的查询，top3未含目标答案字符串且模型答错。后两例提示查询词面相关并不保证检索到所需关系。该批次没有独立语义双审，所以“有效证据搜索率”仍未确定。

这不是原生策略下的端到端收益估计：强制搜索改变了模型输入，而且5题是按历史共同状态回顾性选择。结果支持把**何时继续搜索**列为首要问题；条件性查询和检索已有3/5成功信号，但仍需更大、预先固定的开发集评估。完整逐案报告保存在运行实例`/root/autodl-tmp/v119-bridge/self-query.json`（9.1 KB），入口为`scripts/replay_v119_self_query.py`；实例仍开机，原始报告尚未下载到本地归档。

## 固定50题上的证据缺口提示对照

在冻结的内部开发50题上，以原v118端到端结果作基线，使用相同v118 adapter、1986篇文档、BM25 top3、上下文和解码配置；处理组只在系统提示中增加“先核对问题要求的关系/时间/范围/数量，缺具体事实才补搜”的规则，并限制最多两次实际搜索。结果保存为AutoDL `/root/autodl-tmp/v120-evidence-gap/report-v2.json`。这仍是已暴露开发集上的提示策略诊断，不是独立验证或SFT结果。

基线为14/50 exact match、F1 0.340；提示策略为26/50、F1 0.567，净增12题（13增、1退），正确答案保留率13/14=92.9%。策略在44/50题执行了两次搜索、6题一次；实际搜索总数从66增至94。top3任一结果出现官方答案字符串的题有41道，其中26道模型答对、15道答错；另9道没有字符串命中且均未答对。字符串出现不等于完整关系得到支持，这只能提示答案抽取和检索覆盖都值得审核。

停止约束也暴露了问题：有两次模型试图发起第三次或重复搜索，控制层均拦截；其中一次随后答题成功，另一次仍重复相同查询，最终未产生答案。因此动作协议率为49/50=98%，搜索上限遵守率为48/50=96%。一次原本正确的答案被提示策略改错。虽然后处理组净增明显，保留率低于既定95%要求，且44题都走到第二次搜索，表明该提示还不够有选择性；本轮不据此启动SFT。首版重放曾在拦截第三次搜索后直接结束，未计入上述修正版本指标。

下一步先对13个增益、1个退化及未完成案例进行盲审，逐条确认动作前证据是否真正缺少所问关系、搜索是否补进该关系、答案是否由证据支持。再依据这些审阅结果改进“是否补搜”的判据，并在未用于调策略的开发题上验证搜索次数与保留率；达到保留门槛后再冻结SFT训练样本和新验收集。详细汇总保存在本地 `backups/v118/reviews/v120-evidence-gap-summary.json`；AutoDL逐案报告目前仍只在运行实例中。

## 数据与后续选择

下一轮训练先不追求增加总条数。应从未评测的训练来源采集真实模型轨迹，形成“干扰项提示错误答案但缺目标关系→应搜索”及“关系补齐→应回答”的配对状态；正确答案保留样本必须继续覆盖。具体样本量以问题隔离、双审有效性和这两种缺口覆盖决定。先比较检索补跳与答案抽取的开发结果，再预注册唯一的新模型实验，并另行冻结未暴露的内部验收集。v112是当前固定内部环境下的强参考，v101继续作为原对照；历史v107生成式验证器和v108候选协议均未通过其门槛，故不重复原方案。

本轮代码未更改模型公共接口、adapter或原始冻结报告。新诊断只读取固定开发题及冻结检索语料，没有访问独立100题或final-test。
