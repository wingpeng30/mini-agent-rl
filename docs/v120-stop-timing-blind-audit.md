## 范围与结论

在冻结的 v117 内部 50 题上，v118 adapter 的提示词回放从 14/50 提升到 26/50，出现 13 个新增正确、1 个原正确转错，另有 1 个未完成。正确答案保留率只有 13/14（92.86%），低于预注册的 95%；本结果只能作为开发诊断，不可推广为已通过验收。

对这 15 案，DeepSeek 独立审核者只收到匿名案例的问题、第一次检索的文档开头、第二次查询与新增文档开头、最终输出；没有收到 gold、模型身份、评分及改善方向。主 agent 已知评分与 gold，只负责对盲审结果作证据核对和归因，不充当第二名盲审者。审核的 15 条引用均逐字匹配相应文档的前 900 字；一条引用把两篇文档用 `|` 连在一起，拆开后两部分各自合法。审核记录见 `backups/v118/reviews/v120-blind-api.jsonl`，检索文档 ID 见 `backups/v118/reviews/v120-case-doc-ids.txt`。

**证据结果：**13 个改善中，12 个第一次检索尚缺目标关系，第二次检索新增文档补到了该关系。剩下的 PARIS 案第一次检索已经完整支持 `Situation Publishing Ltd`，第二次检索未增加相关事实；原模型却回答了网站名 `The Register`，因此该改善是答案抽取/关系选择修正，不能记为检索收益。12 个真正补证据的改善中，11 个原轨迹在一次检索后提前回答；Wormsley Park 案原轨迹搜索三次且重复偏向 Leonard Ingrams，属于查询选择问题。

## 问题在何处

同一冻结 adapter、语料和检索器下，改变提示策略产生 12 个真实补证据的改善，说明主要可操作缺口是**回答前未确认目标关系是否已经得到支持**。这属于模型决策与提示策略的交互：提示词可以大幅改善同一模型的行为，因此不能归咎于权重遗忘；但模型仍会在有明确实体线索时选错实体、重复查询或把网站当出版公司，说明仅靠提示词也不可靠。

具体分解：11 案是原轨迹过早停止；1 案是原查询偏移/重复；1 案是证据充分后的关系抽取错误；1 案是新提示下的实体与时间锚丢失；1 案是重复查询后的协议/恢复失败。第二跳查询在改善案中有 1 个未瞄准缺失属性（McCord），虽碰巧检索成功，不应当进入优质 SFT 查询目标。未发现足以确认“训练示例或官方目标错误”是主要原因的证据；Wormsley Park 的业主时间范围值得单独标注，不直接用于停止规则标注。

## 下一版停止条件

1. 每次决定前建立两条内部槽位：`桥接实体/关系` 与 `问题所问属性`。仅在同一实体、时间、范围、单位均由**动作前实际可见句子**支持时回答；把实体名或答案词命中视为不充分。PARIS 案在首轮已满足这一条件，应直接回答。
2. 若缺第二条关系，查询必须包含已确认的桥接实体及缺失属性，例如 `James McCord birth date`、`Stacey King consecutive championships`。对只重复已知关系的查询直接拒绝；禁止从姓名中抽出同名地点替换已确认实体。
3. 检索结果须判断是否真的补入缺失关系；没有新增支持时，不能因为获得新文档或达到两次搜索就声称“证据足够”。达到上限而仍缺证据，应显式给出证据不足的终止动作/可审计失败，不再反复生成搜索。
4. 先在冻结开发题上做**单变量**回放：固定 adapter、检索、top3 和解码，只加入上述停止/查询校验；同时检查 50 题 EM、F1、13/14 原正确保留、协议及无效搜索。只有原正确保留率至少 95%、协议至少 98% 且净正确数为正，才考虑扩大验证。独立 100 题和 final-test 继续封存。

## 审核边界

此轮 API 盲审使用每篇检索文档前 900 字，并按真实检索时序隔离前后证据；原始回放只记录了 prompt token 数和哈希，未保存最终渲染的 token 序列。因此审计能验证引用属于相应时点的检索文档，但不能宣称已逐 token 证明所有引用在压缩后的提示里可见。15 案的关键引用均位于相应文档开头；下一次回放应显式保存每一步的 `budget_messages` 可见片段与哈希，再做严格盲审。此限制不改变退化案的错误实体/年份和未完成案的重复查询结论。

本案只使用内部开发题；未访问独立 100 题或 `final-test`。v111 的 78%仍是训练侧 API 混合流程成绩，不是本地模型成绩。
