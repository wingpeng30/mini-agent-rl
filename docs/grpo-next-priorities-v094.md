# v093 后续任务优先级与执行顺序

更新日期：2026-09-18。状态：P0-1/P0-2/P0-3 已完成；P0-1 的 GPU 数值部分按计划留在 P1-1。尚未启动 GPU 推理、采样或训练。

## 当前事实与目标

起点为 checkpoint-200 非思考模式。v093 完成冻结 5×4 采样，只有 2/5 组奖励非零方差；两组均包含非法动作，另外两组全对、一组全错。没有执行 optimizer 更新，也没有新增 GRPO checkpoint。短序列稳定性通过，不等于长上下文训练与重载通过。依据 reports/grpo-v093-backup 内报告与原始轨迹。

目标是尽快得到可重载、有同协议对照的 GRPO 结果；训练正确性、学习信号诊断、效果验证分别验收。旧 v093 的停止结论保留，新协议使用独立版本与目录。

固定起点与公共参数：checkpoint-200，非思考，BF16，2048 输入、128 输出，compact-v3，BM25-v2，最多三个动作；固定训练前100题构建检索语料，训练温度0.7、评测温度0。开发集与历史探针分别使用冻结的评测语料，所有模型共享同一评测环境；不强求评测语料与训练语料相同。封存 final-test 不参与本清单。

## 最高优先级：现在可以确定并完成的工作

### P0-1：修复训练前向、数值门控及报告绑定（本地）

涉及 src/mini_agent_rl/model/local.py、training/grpo.py、cli.py。

- 生成显式开启适用 KV cache，所有评分/训练前向显式禁用；覆盖生成→评分→更新→再生成的切换。
- 在真实训练模式和相同精确输入上验证更新前 current/old ratio；不能只用两次无梯度评分代替。检查完整输出及终止 token，prompt/tool/padding 不参与 loss。
- 把有限值、输入重放、整组奖励重算、mask、梯度与显存检查放到 optimizer.step 前；更新后另验参数有限值和显存，失败产物不得标为可用 checkpoint。
- 稳定性报告与当前 adapter、tokenizer、代码、prompt 内容、历史策略和检索语料哈希逐项绑定。验证报告过期/内容变化会被拒绝，避免仅比较路径、布尔值或当前指纹与自身。
- 记录生成原始 logprob 与重算 logprob 差异；固定 reference 权重和输出一致性、LoRA-only 更新、保存后重载一致性均建立明确验收接口。
- 为上述失败路径添加有意义的测试，测试必须确认门槛失败时 optimizer 未调用。运行完整 CPU 回归；本地权限失败不算通过。

完成标志：修复及 CPU 回归通过，GPU 待验项明确列出。此时仍不能声明 GRPO 训练通过。

### P0-2：准备一次可自动收尾的执行流程（本地）

- 每个阶段使用独立数据库和目录；冻结命令、任务顺序、代码与数据哈希。逐组保存轨迹、指标和失败原因。
- 用同一总截止时间监督全部子进程；超时终止实验进程组，按预算预留评测、备份和关机时间，不能为重试重新计时。
- 启动前检查实际预算余额、实例身份、基础模型及起点 adapter 的本地可恢复副本。旧六小时是上限，已经使用的时间要计入台账；不能凭“还有额度”自动重开计费实例。
- 预先验证关机通道。网页或官方实例内 shutdown 均需准确匹配实例；记录命令返回与可获得的状态证据，SSH 拒绝连接单独记录，不能冒充控制台状态。
- 备份完整实验记录和可独立重载的 adapter，核对 SHA-256。超过项目既定下载阈值时执行相应确认规则。

完成标志：本地可演练失败、超时、部分结果保存和备份流程；启动前无需临时编写收尾脚本。

### P0-3：冻结下一轮诊断协议（本地）

- 固定训练前30题，每题4条轨迹，seed42；语料仍为训练前100题。前五题已有观测，报告中单列，后25题作为扩大覆盖；不称这30题为独立未见评测。
- 冻结题目顺序与哈希，检查训练题与开发/探针问题重叠；全部题目和失败轨迹保留。
- 分类统计：全对、全错、合法轨迹间奖励差异、包含非法动作的奖励差异。记录查询/动作多样性和奖励分项，区分采样不足、格式问题与语义错误。
- 零方差组可在将来训练中明确跳过；单个零方差组不属于基础设施故障。旧“前五题3组”不用于追认 v093 通过，也不自动决定整个训练集可训练性。
- 第一轮只诊断，不按观察到的奖励重排任务、改 reward 或自动扩量。下一步的样本数、有效更新组目标与一次探索对照参数需要根据诊断冻结新版本后执行。

完成标志：30×4 诊断配置、输出字段、样本边界及停止条件已经写定，可直接运行。

## 下一次开机后的执行顺序

### P1-1：一次完整 GPU 训练正确性验收

前提：P0 全部完成。先做真实轨迹的精确重放与训练模式评分，再做隔离的梯度/optimizer 探测；探测权重不用作正式训练起点。

- 覆盖搜索、回答、非法动作及接近2048输入+128输出的独立压力序列。压力序列只验数值和显存，不作为问答效果证据。
- 同实例严格稳定性通过；更新前 ratio P95 在0.99–1.01，全部在0.90–1.10；无非有限值、输入差异、基础设施错误。
- 核验有限且非零的 LoRA 更新、基础参数与固定 reference 未改变；21GiB 显存门槛按实际统计验收。
- 保存、重新加载后复核参数及固定序列评分，报告加载精度和误差容限。不能用“成功加载”替代一致性检查。

失败处理：保留记录并定位明确实现原因。修复后建立独立版本重新验收；未通过不能正式训练。

### P1-2：完成冻结30×4学习信号诊断

前提：P1-1 通过。执行 P0-3 的冻结配置，完成120条轨迹及奖励独立重算。

下一任务由结果决定：

| 结果 | 下一优先任务 |
|---|---|
| 存在足够合法轨迹间的奖励差异 | 冻结有效更新组目标和任务上限，进入 P2 三seed小训练 |
| 差异主要来自非法动作 | 判断协议错误是否源于实现；若属于模型，可开展明确以协议可靠性为目标的 GRPO pilot，不能据此预期问答提升 |
| 大量全对 | 按预注册的随机顺序扩大训练题覆盖，保留所有组；不按结果挑题 |
| 大量全错且动作高度一致 | 先查看证据是否足够、奖励标签及采样机制；再安排一次单变量探索对照，参数提前冻结 |
| 奖励与证据/答案明显不一致 | 优先修复奖励或数据问题，建立新版本审计，停止效果比较 |

这里的“足够”必须在正式训练前写成数值目标，并结合实测有效组比例和每组成本选择；目前不凭5题结果承诺具体训练规模。

## 条件满足后顺序推进

### P2：三seed正式小规模 GRPO 及快速回归

前提：训练正确性通过，采样诊断已经支持明确的可学习目标，训练协议冻结。

seed42/43/44 都从 checkpoint-200 独立开始；LR5e-6、clip0.2、KL0.02、policy epochs2、梯度裁剪1.0为已有起始配置。具体任务数及有效更新组目标由 P1-2 决定，不能默认机械复用失败的5×4门槛。

三个seed全量报告，保存及重载均验收。使用固定20题开发子集与同实现 SFT 对照；任一seed EM下降超过10个百分点或非法动作率增加超过5个百分点，停止扩量并诊断。

### P3：固定对照评测与扩量决策

先对最后完整通过阶段的三个seed及SFT执行固定100题自主评测和120-case探针。自主按问题配对bootstrap，探针按原问题聚类，seed42、10,000次；跨seed平均差值须共同按问题重采样，不能把重复题目当独立样本。

报告EM/F1、完成率、协议错误、检索行为、实际token、运行耗时和显存。推荐替换SFT仍要求三个seed平均EM不低于起点、至少两个seed不退化、平均非法率不高于起点；只有跨seed平均配对提升区间下界大于0才称有统计支持。

扩到50×4属于后续条件任务：须有小训练及回归证据、三个seed完整训练和评测可完成，并保留20%计算余量及收尾时间。预算不足时优先完成已有模型对照。

### P4：模型使用与性能优化

有可信比较结论后再决定保留GRPO或SFT，交付一条命令复跑、重载、离线演示及使用说明。批量scorer/生成和kernel优化按测得瓶颈排序；思考模式、重训SFT、模型扩容、reward消融目前无必做依据。
