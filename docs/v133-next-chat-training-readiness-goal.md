## 4. 现在创建并执行 Goal M：下一次训练的基本验收

目标：以一次有限检查，回答“现有资产是否足以启动一项有意义的训练，以及应该训练什么”。输出目录 `runs/v133-goal-m-readiness/`。完成标准是明确的可执行结论或具名阻断项，不要求证明唯一机制、不要求已有成绩提升。

### M0｜最高优先：确认训练输入和测量可信

- 白名单限定为 Goal J冻结训练16题、Goal J评价16题、Goal G回归16题、必要adapter/tokenizer/代码和已有审核引用。
- 对实际将使用的记录核对来源、用途、标签、双侧可见证据和审核绑定。原内容与哈希未变且审核范围覆盖的直接复用；不重新全量双审。必要范围内实际看问题和证据，不能只读历史总结。
- 复核生成/监督使用同一渲染及前缀；最后目标assistant定位、标签、因果移位、结束符、padding、长度和答案不混入生成输入。长度沿用提示2048、目标128、总长2176，不截断补救。
- 训练/评价的来源和实体隔离复用冻结证据并核对当前ID与哈希；两组已用评价题继续标为开发用途，不能进入训练、奖励调试选题或checkpoint选择。
- 验证评分区分最终answer、合法search、无效输出，冻结EM/F1不变。
- 只修复确认存在且影响下一轮的实现缺陷，并做相应回归检查。无变化的历史检查不重复运行。

### M1｜一次离线归因，明确本轮训练要优化的行为

复用Goal J/K/L结果，优先分析原提示P0的v118与Goal J配对；L的P1/P2作为补充。对32道开发题输出简洁配对表：

- 两方均有效回答时，内容正确性是否改善；报告分母和题目ID。子集是事后分析，不能替代全体指标或证明因果。
- 其余变化属于继续search→answer、无效→有效、答案粒度、属性选择或无法确定；允许多标签，但不能加总成收益题数。
- 将错误或未决审核保留为限制。g009等开发输出缺票影响“无退步/语义收益”的说法，不自动使已独立合格的训练标签失效。

到此必须选择一个可操作目标，例如“固定证据下的答案质量与完成率”。若属性能力和时机无法彻底分离，可以采用这个联合目标并限定结论；不要为了机制归因再扩展提示矩阵或造新题。

### M2｜只检查选定训练路线所需的实现

先判断现有数据是否还有可学习信号。Goal J训练16题已达到16/16贪心正确，不能直接假定继续SFT或GRPO有用。

若推荐RL，检查：

- 采样、old/current/reference重算使用同一prompt token及动作token/mask；tool和prompt不计入policy loss。
- 固定reference应绑定本次选定的初始SFT adapter，不能误用裸基座；adapter真实激活、只更新LoRA，checkpoint能重载。
- 奖励与冻结任务一致；建议将合法最终回答下的EM/F1作为内容奖励，合法search与无效动作分别记录，不把格式奖励当内容提升。准确权重在采样前冻结，不根据开发成绩调奖励。
- 组内advantage、零方差处理、首次ratio、KL方向、梯度/数值/显存及超时停止均正确。复用现有实现，必要时增加内部入口，不迁移框架。

只有静态检查不能回答“是否有训练信号”时，才做一次最小GPU采样：默认Goal J adapter、训练16题每题4个候选，共64条；seed42、temperature0.7，其他采样参数事先记录。只用训练题判断信号，不采样开发题来挑训练任务；不调用API给每条采样打分。模型计算在AutoDL，启动前通知用户。

探针上限30分钟，首两条估速，失败不自动重试。报告有效奖励差异来自内容还是动作，零方差比例及长度。有效组数量判据必须在生成前写入配置，并说明只是工程可训练性门槛，不是统计显著性标准。没有有效信号时停止该方案，不为满足门槛自动提高温度、改奖励或扩池。

v118已经是SFT权重，可以成为独立RL起点候选，但与“继续改善Goal J”是不同实验。若推荐改用v118，必须说明新的研究问题及同条件对照，不能为了让RL产生梯度悄悄切换起点；本轮不自动连跑多套起点探针。

### M3｜一次性做出决策，不让验收变成长期研究

输出一张表：检查项、实际证据、通过/失败/未决、是否阻止选定训练。

必须阻断训练：错误或未受证据支持的训练标签、上下文/前缀错误、训练与评价混用、加载或更新错误、奖励与目标冲突、选定RL路线没有有效学习信号、数值/资源失败。

通常不阻断开发训练：尚无全新确认集、未完全区分时机与属性贡献、小样本统计不显著、开发输出审核未决。这些限制必须影响结果表述，不能被写成已解决。

CPU核查以半天至一个工作日为目标，GPU探针最多30分钟。检查只做一轮；新发现的具体冲突才补查。超过范围时列出至多三个根本阻断项和各自最小修复，不启动新数据工程。不能以检查预算耗尽为由把失败改成通过。

## 5. Goal N：M通过后的一次固定预算训练（本提示词先交付具体计划）

不要先承诺必须再SFT或必须GRPO。根据M的证据只推荐一条路线：

1. 已有SFT训练和标签正确且选定起点有RL信号：优先一次固定证据回答的LoRA-GRPO。先冻结起点、训练16题、奖励、采样和更新预算、优化器、reference、最终checkpoint与评价顺序，给出准确运行命令。
2. 发现真实监督/编码缺陷影响现有权重：先最小修复，提出一次修复后的SFT及同期对照。不能把“为了更好看再训一次”作为理由。
3. 当前数据/起点没有学习信号：明确停止这条训练路线，保留已完成SFT成果；给出一个最小可行替代方案，不自动造题、不将无效更新算RL成功。

N默认一个seed、一次训练、最终checkpoint，GPU阶段总上限7200秒，包含基线、训练、复评。具体更新数由M提出并在启动前冻结；不能以“在时限内一直试”为预算。失败保留现场，确认技术缺陷后是否重跑另列，不自动调参。

对照至少包含选定SFT起点与RL/修复后模型；训练集和两个16题开发集分别报告EM/F1、有效answer、search、无效输出、新增/丢失正确、耗时/显存及相应训练指标。历史基线只有输入token、adapter和解码环境可核实一致才复用，否则预算内统一重做一次。

拟执行的是固定证据回答训练，不能称作端到端搜索策略训练。如果下一阶段要优化自主检索，需另列有检索环境和多步奖励的方案，不能用当前答案状态代替完整轨迹。

M结束时交付唯一推荐、冻结配置草案、运行命令、预算和未决限制。**本次立即执行范围到M及N的具体方案；不把这份交接的规划本身当作启动N参数更新的授权。** 用户随后明确启动N时，按已冻结方案推进，不重新全量验收或重复索取已给授权。
