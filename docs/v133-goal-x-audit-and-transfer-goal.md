# Goal X：修复历史隔离与题义审核，验证扩大双侧证据训练的收益

## 状态与执行约定

- 执行状态：X0—X2 已完成；X3 按预设四类训练覆盖门槛停止。共同隶属关系类最多 4 个真实可见上下文，低于最低 16；X4、X5 不适用。实际结果见 `runs/v133-goal-x-audit-and-transfer/REPORT.md`。
- 顺序推进 X0→X5；通过预设门槛后自动继续，不重复请求训练授权。
- 保留 Goal W 原始候选、报告、停止记录及哈希。修复结果写入独立目录 `runs/v133-goal-x-audit-and-transfer/`，不覆盖 W，不将 W 的停止记录改称训练成功。
- 远程环境：`ssh -p 25320 root@connect.cqa1.seetacloud.com`；当前 0.8B 模型、单卡环境。无累计 GPU 时间限制或阶段时长上限；持续记录进度、耗时和资源。
- 必要时至多使用两个 `gpt-6-luna`、`low` 辅助 agent，分别协助题义／证据审核和历史隔离复核；主 agent 负责裁定、代码、执行和结论。

## 目标与已知问题

检验：增加真实检索上下文中的高质量双侧证据训练，能否减少单侧属性错误，并在新问题上提高正确、充分且有实际证据支持的搜索回答成功率。

当前起点为 Goal T seed 42、update32，旧题严格 EM 20/32、回归 7/16、无效动作 0。Goal W 没有产生新训练权重或新题收益结论。

已知需要修复：关键词分类误判；仅检查一个类别就推断整个池不足；历史排除遗漏（例如 `5a73583e55429901807dafd0` 已出现在历史评价却进入 W 训练候选）；W 运行器尚未实现完整训练评价流程。

## X0：核查资产、建立完整历史排除索引

1. 读取仓库实际指令与历次数据、训练、评价清单，核对当前起点、基础权重实际文件、tokenizer、代码和依赖哈希。核查远程 GPU；无卡时完成 CPU 工作并通知用户。
2. 汇总历史已使用的问题 ID、规范化问题、主体实体、支持及已用语料标题。来源包括现有历史索引及其后续 Goal G—W 的实际资产；按实际文件查漏，不能仅按 Goal 名称假定覆盖完整。
3. 每条索引保留来源路径、哈希、用途和规范化规则。实体按题义和来源标题识别；不把关键词匹配或不完整实体索引称为完整隔离。
4. 旧封存资料只使用既有排除清单或已验证的重建索引，不打开其题目、答案或输出。无法可靠排除的来源标为未解决；排除信息不足时禁止最终数据冻结。
5. 输出覆盖矩阵、已知遗漏修复及隔离测试。对确认资料仅由隔离的数据审核流程处理，训练和开发分析流程不得读取其内容。

完成条件：已知泄漏用例被检出；历史清单覆盖可追溯，未解决项明确，不虚报完整性。

## X1：对现有 512 道训练候选进行一次完整题义与证据审核

候选来源固定为 W 正式版 `data/candidate-train.jsonl` 的 512 题，保存输入哈希。按固定哈希顺序审核全部题目，不新增候选、不改写问题、不因单类短缺提前结束整池审查。

每题记录：原问题和来源、所问属性、两个主体、自然支持段落、历史重叠、共同属性适用性、双方证据、原答案是否充分、实际语义类别、审核结论及理由。

- 分类按实际题义，关键词只辅助定位。职业、实体类型、隶属关系、来源四类沿用 W；归类定义在审核前写清楚，允许“其他／不适用／有争议”，不得为凑配额强行归类。
- 分开记录：历史重叠、题目不适用、来源证据不足、答案存在歧义、可以进入真实搜索验证。每题可有多个问题，同时记录主要排除原因。
- 不能仅凭答案字面未出现判定证据不足；允许证据支持的同义表达，推断链须明确。
- 对比旧规则类别与修复类别，输出全部 512 题去向和各类剩余量。审核争议仅做一次有证据的主 agent 裁定，不反复改写或扩大池。

开发、确认候选沿用 W 已冻结各 128 题，仅按来源、历史／跨 split 隔离和证据质量审核；不按模型答对与否筛选。不得在 split 之间挪题补足数量。

## X2：实际搜索验证与训练配对，得到真实可训练数量

1. 在 Goal Q 同一产品路径复现旧 32 题基线：20/32、回归 7/16、无效动作 0。未复现时记录差异并停止候选采集与训练，不更改基准。
2. 使用原 Goal T 起点，对 X1 通过的训练候选各运行一次 greedy 搜索，最多 512 条；不重复采样，不手工补入支持文档。
3. 固定 BM25-v2、top-3、原提示、thinking=false、最多 4 次模型调用／3 次搜索、2048 输入／128 新 token。保存真实输入 token、工具返回、截断记录、最终回答前上下文与停止原因。
4. 仅实际最终回答前可见充分双侧证据的上下文可用于配对。未回答、未找齐、截断导致证据缺失与来源证据不足分别计数。
5. 每题一个 chosen/rejected 对；chosen 充分回答同一所问属性，rejected 最多提出 3 个候选，选择具有可说明证据缺陷的一个。等价表达不能作负例。区分事实错误、单侧支持与可见证据不足，保留引用和理由。缺少可靠负例则排除。
6. 不根据起点是否答错排除本来合格的训练题；chosen 可以修正采样答案，但不能改动输入证据。标签仅覆盖最终 answer 动作及终止符。

语料沿用 W 三个独立的 2048 篇自然段落库作为待修复资产，审核历史及跨 split 标题隔离。发现污染必须显式记录；修复只能使用预先冻结、可追溯且不依赖模型成绩的干扰文档来源。若无此来源，或支持材料移除导致规模不足，记录缺口并停止冻结，不能临时新增问题池。

## X3：冻结可执行实验或明确结束于缺口

沿用 W 门槛：128 个训练配对、64 道新开发、64 道新确认；至少四类，训练每类至少 16、开发／确认各至少 8，职业不超过各 split 一半；三库各 2048 篇且符合隔离要求。

- 超额时按审核前冻结的类别配额与哈希排序选择，不按模型成绩挑题。
- 满足全部条件：冻结数据、输入 token、标签、seed 42/43 排列、语义评分规则、支持依据、软件版本和哈希，自动推进 X4。
- 不满足：完成全池审核和适用训练题的真实输入验证，交付按阶段／类别分解的缺口与可用数量，结束本轮。可提出一个具体的小规模方案，但不得自动降低门槛、追加候选、启动该方案或宣称完成 W 训练验证。
- 排除索引无法建立或基础设施失败等硬性问题可提前停止；不得在明知隔离无效的环境下继续采集。

## X4：四次训练与统一开发／回归评价

四次独立训练均从原 Goal T adapter 加载：A 普通答案 SFT、B 序列 logprob DPO，各 seed 42、43。每次固定 128 题一遍、128 次更新；同 seed 两臂输入与顺序相同。

- SFT：chosen 最终动作 token 平均交叉熵；DPO：沿用 Goal U，beta=0.1，reference 始终冻结原 Goal T。
- learning rate=5e-6，AdamW betas=(0.9,0.999)、eps=1e-8、weight_decay=0，梯度裁剪 1，只更新现有 LoRA。
- 只保存阶段末 checkpoint；检查 LoRA 变化、base/reference 不变、独立重载一致。全部训练完成后统一评价。
- 起点和四个候选评价新开发 64 题、旧 32 题、Goal V 已暴露 32 题，各使用冻结的相应语料和同一搜索规则。
- 新开发起点成功数超过 60/64 时，提升门槛不可达到：在训练前结束，不替换题目。
- 主要指标为正确、充分且由实际可见证据支持；严格 EM、F1、事实错误、单侧错误、无效动作、搜索次数和延迟单列。无效、未回答、预算耗尽、无法判定均不计成功。
- 审查隐藏模型和 seed，相同问题／实际证据／答案组合仅判一次，保留引用和裁定理由，标明代理辅助审查。
- 固定上下文诊断回放新开发起点已回答题的实际输入，比较五个模型；缺失题单列，不参与选模。

进入确认的路线须两个 seed 均满足：新开发成功数较起点至少 +4/64；事实错误、单侧错误、无效动作均不增加；旧主要开发、旧回归、V 三组语义成功数分别不下降；工程检查通过。

两臂均合格时依次比较两 seed 中较低成功数、平均成功数、较少事实错误，完全并列选 A。无合格路线则结束并保留当前产品模型。
