## 当前起点与研究问题

固定25条既有有效双审训练answer-state，以及16条来自官方train的固定证据开发题。研究问题是：从同一v118 adapter继续一次有限SFT，能否在同一16题上更准确地输出证据中的所问值？开发集不是独立确认集，也不测试端到端搜索。25/16之间无来源ID和归一化问题重叠不等于已证明开发题从未进入基座或v118历史训练。

冻结配置：`configs/v133-goal-c-small-sft.json`。冻结清单：`data/evidence-sft-v133-goal-c-private/frozen/freeze-manifest-private.json`。原始输入文件和审核票保持可追溯；本轮不补数、不重启48条已作废审核包，不复审整个旧池。

## CR0必须检查的具体风险

1. 当前脚本只经过语法/CPU数据检查，没有经过真实训练或推理验证；本计划不将“准备完成”解释成运行已验证。
2. 评估器虽然记录配置哈希，仍须检查其执行前绑定是否完整，补齐基座文件、tokenizer、adapter配置及训练产物与本次run的关联。
3. 当前评分代码包含ASCII归一化，不能未经核对就称与官方SQuAD实现完全一致。运行前明确记为本轮固定归一化EM/F1；任何评分实现修正必须先登记，两组共用，输出后不因成绩改变口径。
4. 训练与评估runner存在Windows绝对路径；AutoDL不能照抄本地命令。迁移只允许改资产位置和执行环境绑定，保持内容哈希、输入与实验设置一致。原清单保留，另存路径映射/执行清单。
5. 当前源池manifest在冻结后有更新；核查冻结清单引用的是历史快照还是当前文件。差异如仅为配置/审计更新，追加可追溯说明；不能静默改历史哈希使其看似从未变化。
6. 单次运行应在加载模型前写入启动记录，失败后保留。超时/OOM后的残留文件不能被误当成已完成checkpoint或允许自动第二次训练。

## 预算、速度检测与停止规则

- GPU计算最多两段：SFT最多60分钟；32个配对输出合计最多60分钟。两段总GPU进程墙钟上限120分钟，包括各自模型加载；不保证传输、CPU检查及外部审核也在两小时内结束。
- 速度检测取正式训练前两个完成的optimizer step、正式评价前两个输出，保留这些正式结果，不另跑smoke。将已经消耗的加载时间、当前吞吐和剩余工作计算成预计总时长；若预计超出该段60分钟则提早终止并报告估算，不等待用满预算。
- 训练只运行一次、一个seed、一个最终checkpoint；不搜索学习率、epoch、prompt或搜索预算。评价不因失败案例补跑。
- 无收益是有效结论。技术失败是运行不可判定，不等同于研究假设失败；无新授权时不启动修复后的第二次训练/推理。
- 未达EM门槛时直接交付计算结果与停止结论，不为负面结论强制新增整批付费审核。
