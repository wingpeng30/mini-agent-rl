# v116 SFT 前数据与诊断准备

本轮只构建、审核并冻结数据，不启动 SFT，不开 AutoDL，不访问独立 100 题或 `final-test`。v111 的 78% 始终是训练侧 API 混合流程成绩，不能当成本地模型成绩。

## 已固定的输入与来源

- HotpotQA distractor 官方训练分片共 90,447 题；下载清单记录分片行数和 SHA256。历史暴露扫描覆盖本项目已有训练、构造、诊断与评测 JSON/JSONL；封存测试内容不读。任何扫描失败都会阻断数据门槛。
- v114 已双审通过的通用训练池为 332 状态、186 题。其中 62 题具有非空证据搜索与回答两种状态。v116 从既有备用池固定顺序选出 60 条互补训练候选，均须重新双审，不能直接算合格数据。
- 新内部候选来自历史未暴露的官方训练题，按源 ID 哈希确定顺序，仅用题目质量、可构造证据和风险覆盖选择。冻结 50 题、100 个搜索/回答配对状态；旧内部 50 题留在开发诊断集。新内部候选与训练候选尚须语义审核，不能以答案字符串出现代替审查。
- 题面预审排除 19 道明显多指向、缺时间锚或残缺题，逐题原因见 `data/evidence-sft-v116/internal-question-quality-exclusions.json`。修订前候选包保留在本地备份及 `superseded-internal-v1`，正式审核仅使用最终哈希的内部包。
- 首轮内部单审发现 10 道题在现有共享语料中缺关键实体关系、答案数值不符或搜索早已不必要；按证据可构造性排除，理由见 `internal-review-quality-exclusions.json`。首轮100状态原包和审核保存在 `superseded-internal-v2`。重建统一检索语料后100个状态的包哈希均变化，因此不能继承先前审核。第二轮在新包上重新审核，结果另行汇总。
- 第二轮审查所用 `internal-revision-pending.jsonl` 与规范 `internal-packets.jsonl` 的100个 JSON 对象逐项相同，但空格使文件字节哈希不同；`review/internal-revision-manifest.json` 分别冻结两份文件和五个20条批次的哈希，避免把不同文件哈希误认为包变更。
- 新候选来自程序构造的状态，来源字段明示；不宣称是本地模型真实轨迹。训练导出只保留输入与目标动作，源 ID、审核、gold 和映射分开保存。

## v115 诊断修复

原始 v115 报告保留。新盲审包将证据严格绑定匿名候选与决策步；搜索返回文档仅作为该次检索收益证据或下一步的可见证据。搜索必要性、查询依据及 top3 新增相关证据独立判断，缺结果记不可评估。原 117 案例中，受旧引用边界问题、分歧或不确定影响的 90 案例重审。引用必须逐字包含于相应候选、相应决策前的截断证据；无效引用不进入结论。

单名盲审者完成90案，并以追加侧表修正其中39案的逐字引用；原裁决保持不变。第二名使用项目上一级目录 `.env` 指定的 DeepSeek 模型独立审核同一盲包。270个匿名判断中84个获得一致且确定的证据支持结论；186个仍未解决，其中180个是实质分歧、3个双方不确定、3个含无效审核。不得把未解决判断算作支持或退化。

固定状态原始动作统计：充分证据下正确回答 28、继续搜索 5、未匹配目标的回答 11；证据不足下搜索 50、未搜索或动作无效 6。端到端官方评分变化是 4 增、1 退。这些是不同维度；证据语义变化在独立双审完成前保持未解决，不能据此判定遗忘。

## 数据放行条件

仅同一状态的两名互不接触审核者一致批准、逐字引用合法且文件哈希匹配时收录。训练集须 300–400 状态、至少 150 题、至少 75 道完整非空搜索/回答配对题；回答占 45%–55%，非空证据搜索至少 40%，空证据搜索至多 10%；关系、时间、范围、测量各至少 20 条。内部集须恰好 50 题、100 状态，每题搜索及回答各一，四类风险各至少 5 条。两集合按源 ID 与规范化题面隔离，内部集还须与历史暴露隔离。输入≤2048、目标≤128、完整序列≤2176 token。任何门槛失败不得启动训练。

当前缺口以 `reports/v116-sft-preflight.json` 和 `reports/v116-v115-semantic-merge.json` 为准。评分与证据支持变化的逐案对照见 `reports/v116-v115-score-vs-evidence.json`：官方端到端4增1退中，4增均获双方确认有证据支持改善，1退证据支持变化未解决，不能归因为遗忘。下一次训练配置在 `configs/v116-next-sft.json`：从 v101 分别新建 5 步 smoke 与独立 50 步正式 adapter，正式使用最后 checkpoint。远端 GPU、权重与逐 token 一致性待下一次开机后、训练前核实。本轮不启动训练。

第二轮内部单审最终100/100，91条批准、9条拒绝，只形成45道完整搜索/回答配对题。DeepSeek 双审后只有72条状态获双方批准，其中64条组成32道完整配对题，距50题差18题；完整配对池范围风险仅2条，距最低5条差3条。训练补充候选60/60单审中34条批准；双审后25条获双方批准，按固定最小选择规则取13条，与旧332条组成345状态、75道完整配对题，训练侧动作和风险门槛通过。训练侧纯输入/目标文件单独暂存，清单明确 `training_allowed=false`，直至内部集也通过。直接沿用程序构造的“支持句齐全”标准会把提前可答、目标时间不匹配以及同名人物混淆的样本误标，故拒绝样本继续隔离。

用户已明确授权向 `api.deepseek.com` 传输盲审所需的题目、实际可见证据与匿名目标动作。请求未包含 gold、模型身份或私有映射。API 的地址与模型均从 `D:/AgentLightning/.env` 读取；密钥未写入报告。调用逐条保存、按哈希续跑，不恢复费用账本。初次结构无效记录和补审记录均保留，未通过结构校验的判断隔离。

## 下一轮数据修复

先补内部18道完整配对题及至少3条范围风险状态，不动已过线的训练侧选择。现有50题共享语料若替换问题会改变所有检索输入，第一轮替换10题后旧100条审核包哈希全部失效；因此不能只把新题的审核结果拼到旧包。更稳妥的方案是在使用任何审核结论之前，按固定哈希顺序预选足量且未暴露的训练来源题，先做题面歧义筛查、非空搜索前的缺失事实检查、查询依据检查和 top3 新增关系证据检查，再**一次性冻结较大的候选检索语料**。对该精确语料下的候选状态双审，最后仅从双方批准的完整配对中按既定风险覆盖规则选50题；评测仍用这份原样冻结的语料。若要坚持评测语料只包含最终50题上下文，就必须在选出50题后重建检索状态并重新双审，不能移植旧哈希审核。任何一种方案都不得用模型成绩选题，也不得将单审或争议样本补足缺口。
